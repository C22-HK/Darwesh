Darwesh Group · Design System Audit

Forty-two pages, ten golds, one brand.

You approved two reference screenshots as the final visual language. Both are screenshots of pages already in production — map.html's toolbar and index.html's hero. The approved look already exists. The problem is everywhere else.

The core finding: the site has one real token file (css/profile-tokens.css, the Obsidian / Darwesh Gold / Warm Ivory system) that the shared header, footer, mobile nav, and most public pages already build on correctly. Alongside it, four more token systems evolved independently — admin's --ash-*, Arena's --ar-*, MAM's --mamco-*, and map.html's own hand-rolled “bronze” palette — plus a long tail of pages that hardcode raw hex instead of referencing any of them. Nine button systems, five segmented-control systems, seven card systems, eight badge systems. This is a consolidation problem, not a redesign problem.

02 · Fragmentation

What's actually inconsistent, by component

Every category below converges on the same shape: one reasonably shared system already exists, and several more independently-authored ones sit alongside it — sometimes in the very same file.

Color tokens 4 namespaces + hardcoded outliers

--ps-color-* / --brand-* (css/profile-tokens.css) is the canonical Obsidian / Darwesh Gold / Warm Ivory system, mirrored in tailwind.config.js and reused by css/cinematic.css. Three more namespaces evolved in parallel:

  • --ash-* — admin.html only. Deliberately not loading profile-tokens.css (an explicit code comment explains why). Close in spirit (#c69a4b gold is identical) but different neutral hexes.
  • --ar-* — Arena pages. Own re-seeded obsidian/gold/ivory ramp.
  • --mamco-* — MAM chat panel + spatial UI. Own obsidian/gold ramp, sometimes mixed with hardcoded hex fallbacks in the same rule.
  • map.html's own family — ~910 lines of inline styles, no custom properties at all. Two golds live inside this one file: a solid-fill #B89A63 "bronze" (shared with css/darwesh-marker.css, sell.html, MAM chat) and a newer translucent rgba(224,190,130) "smoked champagne glass" — the exact accent visible in the approved Map reference on the Buy/Explore pills.

Buttons 9 systems

Only three classes see real reuse: .auth-btn-* (3 pages), .vr-btn (7 pages, one embedded widget), .ps-tab for tabs (9 pages). Everything else — .w-btn (home only), .vj-btn/.vjc-btn (verify only), .ar-btn (arena only), admin's .ash-detail-btn*, map.html's own local button vocabulary, org-projects.html's own .op-btn — is page-local. The dominant pattern on buy.html, rent.html, agent.html, offer.html, and work.html is no class at all: the same Tailwind utility string hand-retyped independently at every call site.

Segmented controls 5 systems

map.html's own Buy/Rent/Sell + Explore/My Properties control — the approved reference — is the best implementation in the repo (sliding pill, glass-gold active state). But its own file also contains a second, contradictory pattern for Map-type and filter chips: a solid #B89A63 fill with dark text, not the glass treatment. Admin, profile pages, and account.html each independently reimplement an underline-tab pattern with no shared class between them.

Cards 7 systems

The good news: seven differently-named card classes (.proj-card, .ar-card, .home-property-card, .svc-provider-card, etc.) already converge on the same token values — one recipe, seven names. The bad news: .fav-card (account.html, reused by the alerts panel) hardcodes its own hex instead of tokens, admin's .ash-entity-card sits in the separate --ash-* namespace, and browse-grid cards on buy/rent/listing use raw Tailwind with no class at all.

Panels, drawers & modals 4 systems

map.html's dark-glass blurred #mapDrawer is the strongest pattern in the repo. A second, unnamed convention (fixed inset-0 bg-black/50, toggled via .hidden) is reused — but never componentized — across map's Save-as-Alert modal, listing.html, rent.html, org-projects.html, and several admin overlays. Admin additionally has its own AdminDialog component and a separate .ash-detail-panel bottom sheet, both solid-surface with no blur, visually distinct from map's glass drawer.

Forms 5 systems

.ps-input/.auth-input is a genuine, well-used shared primitive (14 pages). buy.html/rent.html's filter forms use the same token names via raw Tailwind but no shared class, so radius and focus rings already drift input-to-input on the same page. Admin (--ash-*) and Arena (--ar-*) each have their own input styling. map.html's drawer inputs hardcode rgba directly. The one custom toggle switch in the whole site is map.html's — rent.html's conceptually identical "Verified only" filter is a bare native checkbox.

Badges & status pills 8 systems

The sharpest collision in the audit: agent-dashboard.html hardcodes a fork of admin's .badge-sale/.badge-rent/.badge-verified class names with entirely different hardcoded colors — if both stylesheets ever loaded on one page, they'd collide. Admin itself ships two overlapping badge systems on the same page (admin-legacy.css and admin-shell.css). account.html has a third, independent system. The token-based .ps-badge exists but only reaches 8 professional-profile pages — agent.html, work.html, verify.html, and offer.html use none of it.

03 · Against the reference

What specifically contradicts the approved images

Your brief rules out bright/orange/mustard/neon gold, a second glass style, and mixing old UI with the new. Here's what's live today that breaks those rules, distinct from ordinary token drift above.

  • A second glass style, inside the reference file itself. map.html's chip/Map-type toggles use a solid #B89A63 fill, not the "smoked champagne glass" the reference screenshot actually shows on Buy/Explore. This needs to converge on the glass pattern, not the other way around.
  • A more saturated, "cinematic glow" gold (rgba(216,182,101), 46 uses in cinematic.css hover/focus states) sits noticeably closer to the "neon gold" the brief explicitly rules out than the restrained #C69A4B/champagne-glass family does.
  • Admin bypasses its own accent token in 7 places with a brighter, unmanaged #D9B76A — exactly the kind of uncoordinated small gold usage the brief calls out.
  • Two dead Deep-Navy fragments (#031D39, #071B2F) are still live in signup.html, signup-professional.html, agent-dashboard.html, and admin-legacy.css — the exact "corporate/banking blue" cinematic.css's own header says the brand deliberately moved away from.
  • Colliding badge class names with different colors (agent-dashboard.html vs. admin) is precisely "mixing old and new styles" under one class name.
  • Notification bell dropdown is a fully separate light theme (white background, near-black text, its own status colors) dropped onto an otherwise dark header — the single most visually jarring inconsistency found.
04 · Proposal

One token system

Adopt css/profile-tokens.css's Obsidian / Darwesh Gold / Warm Ivory system as the single canonical source — it's already the most widely used, already what the shared header/footer/mobile-nav render through, and requires the least migration. Extend it with two things it's missing today, then retire the other three namespaces into it.

◆

Formalize the glass-gold accent

Seed: map.html's rgba(224,190,130) treatment

Add --ps-color-accent-glass as a first-class token alongside the existing flat --ps-color-secondary (#C69A4B). This is the literal accent in your approved reference — it becomes the canonical "selected/active" treatment for segmented controls, active tabs, and primary CTAs, replacing solid-fill golds everywhere.

▦

Adopt a real spacing/radius/shadow scale

Seed: css/admin-tokens.css's --space-*/--radius-*/--shadow-*

The public site has no explicit spacing scale today — admin already built one. Generalize it from --ash-* naming to --ps-* and make it site-wide, so "elegant spacing" is enforced by a token, not eyeballed per page.
